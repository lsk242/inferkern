# Review: theory and proposal gaps → decisions

Date: 2026-10-31. Reviewer: implementer (pre-Phase 1 scaffold).

## What was solid
- Vision and non-goals well scoped. Two-layer init (dumb PID1 + LLM child) is the right split.
- Prior-art survey thorough; gap claim (“no LLM-as-PID1”) holds.
- Base-options ladder (Alpine → Debian fallback → Buildroot) is pragmatic.

## Gaps / incompleteness found
1. **Goal format ambiguous.** `docs/use-cases.md` shows `goal.md` with inline
   YAML inside a markdown fence — not parseable without custom logic. No schema.
   *Decision:* goals are `goal.yaml` (pure YAML). Fields: `name`, `description`,
   `budget{max_steps,max_tokens,timeout_min}`, `llm{endpoint,api_key,model}`,
   `accept[]` (globs to `checks/*.sh`), `constraints{allow[],deny[]}`. See
   `inferkern/agent/goal.py` and `goals/*/goal.yaml`.

2. **No LLM API chosen.** Roadmap lists “pick first LLM API” as open. Iteration
   needs a swappable endpoint now.
   *Decision:* OpenAI-compatible `POST /v1/chat/completions` with `tools`.
   Env vars `INFERKERN_LLM_ENDPOINT`, `INFERKERN_LLM_API_KEY`, `INFERKERN_LLM_MODEL`
   override goal file. Works with OpenAI, OpenRouter, self-hosted llama-server, etc.
   See `inferkern/agent/llm.py`. If unset, agent runs in heuristic (scripted) mode.

3. **Tool-calling protocol unspecified.** Doc says “tools: exec, read/write, …”
   but not how the LLM invokes them.
   *Decision:* OpenAI function-calling `tools` with JSON schema per tool. Fallback:
   parse `{"tool":..., "args":{...}}` from free-form text (for models without native
   tool use). See `inferkern/agent/tools/registry.py`.

4. **No journal/state schema.** Doc says “journal + facts” but no format.
   *Decision:* `State` persists `facts.json` (latest snapshot) + `journal.jsonl`
   (append-only JSON lines). Journal tail is fed to LLM as context. See
   `inferkern/agent/state.py`.

5. **Policy gate vague.** “Allowlist + denylist” with no matching rules.
   *Decision:* `Policy` matches tool names and `tool:path` prefixes (e.g. `write:/etc`
   allows `write_file` to `/etc/nginx/*`). Deny wins. Empty allow = allow all.
   See `inferkern/agent/policy.py`. Tests in `tests/test_policy_goal.py`.

6. **Supervisor unspecified for Docker vs VM.** Doc sketches a supervisor binary
   but not how it differs between Docker entrypoint and QEMU PID1.
   *Decision:* One Python supervisor (`inferkern/supervisor/sup.py`) handles both:
   auto-detects container (/.dockerenv / cgroup), skips mounts/network in Docker,
   does mdev/DHCP/state-disk discovery in VM, spawns agent with restart budget
   and rescue shell. In Docker it runs oneshot; in VM it loops + steady-state
   re-checks. See `inferkern/supervisor/sup.py`.

7. **VM rootfs construction hand-waved.** “Alpine mini rootfs + stock kernel”
   with no steps.
   *Decision:* Concrete `vm/build-rootfs.sh` pulls `alpine:3.20` via Docker,
   installs deps, copies `inferkern/` + `goals/`, writes `/usr/local/bin/inferkern-init`,
   exports tarball + unpacked `vm/rootfs/`. `vm/run-qemu.sh` builds disk images
   and boots with `-kernel/-append init=/usr/local/bin/inferkern-init`.

8. **Idempotency assumed not enforced.** Doc says “tools must be idempotent”
   but has no mechanism.
   *Decision:* Tools are written to be safe to re-run (`apk add` is idempotent,
   `write_file` overwrites, `service_start` checks before starting). No extra
   framework — convention + journal replay. Future: could add dry-run diffs.

9. **No harness concrete design.** Proposal D is “the test rig” with no impl.
   *Decision:* `harness/run.py` v0: runs the agent N times from clean state
   (local heuristic mode, or `--docker`), records exit code + check results +
   elapsed time, exits 1 if any run fails. JSON output optional.

10. **LLM token/step budget story vague.** Docs say “hard stops” but not where.
    *Decision:* Loop enforces `max_steps`, `max_tokens` (sum of usage.total_tokens),
    and wall-clock `timeout_min`. Env overrides: `INFERKERN_MAX_STEPS`,
    `INFERKERN_TIMEOUT_MIN`. LLM errors trigger backoff and eventual heuristic
    fallback after 3 failures.

## Out of scope for this pass (intentionally deferred)
- Local GGUF inference (llama-server) — remote API first is sufficient for Docker/QEMU demos.
- Secret vault / TPM — env vars for v1, documented as known limitation.
- Buildroot appliance — scaffold targets Docker+QEMU; Buildroot is Phase 3.
- Cost telemetry — harness records success + time; per-token cost reporting needs real LLM traffic.
- Formal verification of tool idempotency — manual review + tests for now.

## Risks that remain
- Heuristic planner is minimal (web-server only). Real LLM reasoning is the intended path;
  heuristic exists so the repo is demo-able without an API key.
- QEMU disk-image creation needs `qemu-img` + either `guestfish` or `sudo` loop-mount;
  without those, user must boot via kernel/initramfs path or prebuild image elsewhere.
- Alpine nginx “user nginx” config assumes the `nginx` user exists (it does in apk package);
  Debian fallback would need different package names.
